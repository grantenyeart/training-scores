Training scores

Every test across every training reports to one sheet and one inbox. This page is how you add a test to anything, now or a year from now, without rebuilding the plumbing.

Status: live. Scores post to the Apps Script behind Rapid Reach Training Scores and email Grant on every submission. Nothing to set up for a new test, copy the template and it reports on its own.

1How it works

One file holds the endpoint. Every quiz loads that file. No quiz contains a URL, so there is never a day where six quizzes point at five different places.

quiz page  ->  score.js  ->  Apps Script  ->  Google Sheet
                                           ->  Grant's inbox

Change the endpoint once in score.js and every test on every site picks it up on the next page load. You never edit the quizzes.

2Adding a test to any training

Copy template.html into the training's repo. Edit two blocks and nothing else.

const CONFIG = {
  title: "Product Knowledge",   // heading, email subject, sheet column
  track: "Closers",             // Setters, Closers, Everyone
  pass:  11,                    // how many right to pass
  back:  "./"                   // where the back arrow goes
};

const Q = [
 {q:"The question.",
  a:["Wrong","The right answer","Wrong","Wrong"],
  c:1, e:"Why it is right. <b>Bold the part that matters.</b>"}
];

c is the index of the correct answer counting from zero, so the second option is c:1. The question count, the progress bar, the intro copy and the scoring all read themselves off Q and CONFIG. Add or remove questions freely, just keep pass sensible.

4Things worth knowing

  • The row is written before the email is attempted. If Gmail hiccups or you hit the daily cap you lose a notification, never a score. The sheet is the source of truth.
  • Retakes do not overwrite. Every attempt is its own row and its own email, so you can see who failed and came back.
  • Gmail caps script mail at 100 a day. Not a concern at your headcount.
  • Names are typed, not picked from a list. If two people share a first name the sheet is what tells them apart.
  • The result screen always confirms. It tells them the score went to Grant whether or not the post actually landed, because a trainee can do nothing about a failure and alarming them helps no one. The honest check is the sheet. If the endpoint is missing, score.js logs a warning to the browser console rather than putting an error on screen.
  • Nothing here is client facing. Internal training only.
